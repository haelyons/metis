# m5 data contracts (what test authors may rely on; implementers keep this file current)

## Run identity and agent chat names
- `args.blind` is a boolean, default false. `args.raid`, when supplied, is a non-empty single-line string and takes precedence over automatic selection. `launch.js stage --stage m5` also accepts `--raid <name>` and `--blind`.
- `m5/raids.json` is `{theme, public, blind}`: a theme string and two ordered arrays of base names. The heist theme uses separate public and blind lists. Automatic selection skips names already present in `m5/raids_used.jsonl`; after the base names it cycles through the same list with suffixes `2`, `3`, etc. Explicit names are recorded too.
- Each ledger row and `C/raid.json` has exactly `{raid, blind, run_root, utc}`; `run_root` is absolute and `utc` is an ISO UTC timestamp. Reservations are serialised. A run reuses its existing reservation and rejects conflicting raid/blind arguments. The launcher reserves against the original pipeline ledger before freezing its copy.
- m5 sets `args.chat_prefix = "x-<raid>"`. Other scripts opt in using `args.chat_prefix`, an agent option `chat_prefix`, or the workflow flag `--chat-prefix`. Without a prefix, runner naming stays unchanged.
- Names are `<chat_prefix>-<label>[-<descriptor>]`; labels are lowercased, non-`[a-z0-9-]` runs become `-`, edge hyphens are removed, and an empty label becomes `agent`. Concurrent sibling calls sharing a label within a stage add `1of<n>`, `2of<n>`, etc. Repair turns add `retry<k>` (starting at 1); fallback calls add `fb`. When needed together, descriptors appear in that order, separated by hyphens. Harness repair calls supply agent option `retry: 1`.
- wf passes the name to every runner as `name`. OpenCode uses `--title`, Claude uses `--name`, and Codex prepends `[<name>]` as the first prompt line, before role instructions.
- The pipeline writes `S/OPERATOR_TAKEAWAY.md` from validated signatures after all stage records, with the raid only in its header. `m5/operator_takeaway.py` accepts optional `--raid`; its Python `takeaway(records, raid=None)` API preserves the old header when omitted. Raid is not added to stage facts or v1 signature IDs.

## A/intake/ (written by the intake agent; checked by the pipeline)
- benchmark.json, data.json: non-empty JSON objects.
- anchors.json: an array; each item has a unique non-empty string `id`, non-empty `quantity` and `source`, finite numeric `published_value`, and `tolerance`. Its length must equal facts.anchors_count. Zero is a valid published value or tolerance.
  - Optional `comparison` is one of `"=="` (the default), `">"`, `">="`, `"<"`, or `"<="`. For `"=="`, an anchor passes when `abs(measured_value - published_value) <= resolved_absolute_tolerance`. For inequalities, it passes when `measured_value <comparison> published_value`; tolerance is ignored and may be 0. Intake should specify `comparison` when the published criterion is a threshold.
  - `tolerance` is a finite nonnegative number (absolute tolerance), or an object with exactly one key: `{"abs": x}` or `{"rel": x}`, where `x` is finite and nonnegative. For `"=="`, relative tolerance resolves to `x * abs(published_value)`; a zero reference therefore requires exact agreement.
- baseline.json: non-empty repo, build_commands, run_commands and published_configuration, plus commit or pin.
- EXECUTION.json: non-empty representative_scale, inputs, outputs and timing_scope. Optional `timeout_s` sets the common script timeout (default 3600 seconds); optional `timeouts` object has `setup`, `run_anchors`, and/or `profile` to override individual script timeouts. Each supplied timeout is an integer in [1, 999999999] seconds. The setup timeout also applies to each harness upload; each script's timeout applies to its one allowed retry.
- The intake passes only when the files are complete and found is true, anchors_count >= 1, data is "available", licence is "permitted", and stock_environment is not false.

## A/results/probe/probe.json (collected before the harness agent)
- The pipeline uploads the committed `m5/box_probe.sh` and runs it through boxrun in the same remote working directory as the harness. Both operations write receipts under `C/receipts/`, using the setup timeout. Fetched `out/probe.json` is validated as a JSON object and copied to `A/results/probe/probe.json`. Logs and fetched `out/` remain under `A/results/probe/`. Stale local or remote probes cannot satisfy a new run.
- Fields match the probe script:
  - `os`: null or `{id, version_id, pretty_name, version, name}` from `/etc/os-release`, with nullable strings; `kernel`: string or null.
  - `nproc`, `memory_kb` (MemTotal in KiB), `disk_home_avail_bytes` (available bytes on `$HOME`'s filesystem): integers or null.
  - `nvidia`: null or `{gpus, driver_version, cuda_version}`; `gpus` is an array of GPU name strings, versions are strings or null. CUDA here is the driver's reported CUDA version.
  - `nvcc`: an array of `{path, version}` for deduplicated executable paths from `command -v nvcc`, `/usr/local/cuda*/bin/nvcc`, and `/usr/lib/cuda*/bin/nvcc`; `version` is captured `nvcc --version` text or null. Missing nvcc yields `[]`.
  - `cmake`, `gcc`, `g++`, `make`, `git`, `python3`, `pip`: null or `{path, version}`, with a string path and nullable version text. `pip` falls back to `pip3`.
  - `apt_sources`: an array of `{file, lines}` naming apt source files and their lines mentioning cuda or nvidia. Commented matches may be included when no uncommented matches exist; these do not authorize enabling a repository. Missing matches yield `[]`.
  - `sudo_nopasswd`: boolean indicating whether `sudo -n true` succeeds.
- Individual missing tools or unavailable facts yield null/empty collections without failing the probe. Probe upload/run failure, nonzero boxrun exit, failed fetch, or missing/invalid JSON fails reproduce with `error_class: infra`, before any harness call; the probe has no agent repair.
- Full JSON content is included in the harness prompt and every setup, anchor, and profile repair prompt. Agents must use discovered paths and versions and never hard-code a toolkit path absent from the probe. Missing tools may be installed with apt only from listed sources, without adding repositories; otherwise only cmake may fall back to pip. If neither route applies, scripts must fail with a clear message.

## A/harness/ (written by the harness agent)
- `setup.sh`, `run_anchors.sh`, `profile.sh` are bash scripts. The pipeline invokes them as `bash harness/<name>` from one fresh `/tmp/m5-<uuid>` directory on the already-running operator-managed box. They share that directory across reproduce and profile. No dev lifecycle commands are issued. `BOX` and `FETCH` are inherited unchanged by `boxrun.sh`, including injected executables.
- `setup.sh` installs/builds the exact published baseline in the stock image; sudo is allowed only for apt. Published source/configuration stays under `baseline-published/`; inputs stay under `data/`. Setup must tolerate one retry in the same directory. Tuning is deferred.
- `run_anchors.sh` runs the published protocol at the intake's representative scale and writes `out/anchors_measured.json` as an object mapping each intake anchor ID to a finite measured number. Missing or non-numeric measurements fail the corresponding anchor; booleans and nonfinite values count as non-numeric. Additional measurements are ignored for scoring.
- `profile.sh` runs the baseline once at representative scale, with stage wall timers and `nvidia-smi` sampling. It writes `out/profile/stages.json`, `out/profile/total_wall_s.json`, and raw telemetry under `out/profile/`. Unavailable GPU timings remain null; scripts must not substitute allocated GPU time.
- Harness prompts require the published build and binary to run and measurements to come from their OUTPUT. Scripts must never parse or assert on source text. Measurement checks fail only on missing or invalid output; deterministic scoring owns anchor comparisons.
- There is one initial agent call (`harness`, `ls-writer`, `sonnet`). Each script independently permits one repair after a nonzero exit: `harness-repair` for setup, `anchors-repair` for run_anchors, `profile-repair` for profile, with the same role/model. The agent receives at most the last 200 lines of that script's log and may rewrite only that script. Only that script is recopied, then rerun once with its original timeout. Infrastructure/fetch failures do not trigger repairs. A second failure stops the stage; failed scientific measurements are never retuned by repair.

## A/results/reproduce/ and deterministic anchor scoring
- Every reproduce box command fetches remote `out/` into `A/results/reproduce/out/`, and its `<receipt-id>.log` into `A/results/reproduce/`. Logs remain in the agent view. The local fetched `out/` is cleared before each command to prevent stale measurements. The final copy contains the anchor run's outputs.
- `python3 m5/score_anchors.py <anchors.json> <measured.json> <out.json>` writes an atomic JSON object with exact keys `anchors`, `anchors_passed`, `anchors_total`, `all_passed`.
  - `anchors` preserves intake order and contains `{id, published_value, measured_value, tolerance, passed}` for every anchor. `tolerance` preserves its input form; `passed` is boolean. Missing or non-numeric measurements are represented by `measured_value: null`. Failed rows additionally contain `reason`: `unknown_comparison`, `missing`, `non_numeric`, `out_of_tolerance` (for `"=="`), or `threshold_not_met` (for inequalities). Unknown comparisons take precedence over measurement failures; missing measurements take precedence over non-numeric measurements. Passing rows have no `reason` field.
  - `anchors_passed` and `anchors_total` are nonnegative integer counts; `all_passed` is boolean. Empty anchor arrays, duplicate IDs, invalid published values, invalid equality tolerances, and nonfinite calculated equality differences/tolerances are parse errors. Unknown comparisons and missing/non-numeric measurements are anchor failures rather than parse errors.
  - Exit 0 means every anchor passed; exit 4 means at least one anchor failed; exit 1 means invalid/missing input or an output write failure. Invalid input does not produce a new score file. Diagnostics contain no input content.
- The pipeline writes the score to `A/results/reproduce/anchors_scored.json`.
- Reproduce facts are `{anchors_passed, anchors_total, stock_verified, tuned_control_valid}` plus common `tokens_known` and `gpu_busy_known`. Counts remain null until scoring succeeds; `stock_verified` is true only after setup exits 0; `tuned_control_valid` remains null. The gate passes only when stock is verified and every anchor passes. `run_valid` is true/false when anchor scoring passes/fails.

## A/results/profile/ and A/profile-packet.json
- Profile fetches remote `out/` to `A/results/profile/out/`; logs are `A/results/profile/<receipt-id>.log`. Its timing inputs are therefore under `A/results/profile/out/profile/`.
- `stages.json` is a non-empty array of `{stage, wall_s, gpu_s}`. `stage` is a non-empty string; `wall_s` is finite nonnegative seconds; `gpu_s` is finite nonnegative seconds or null and must be present. Stage wall times must describe critical-path coverage without double-counting overlap. Extra input fields are not copied to the packet.
- `total_wall_s.json` is an object with finite positive numeric `total_wall_s` in seconds. The sum of stage wall times must also be finite.
- The deterministic pipeline writes `A/profile-packet.json` with exact keys:
  - `stages`: the validated timing rows, each augmented with `wall_fraction = min(1, wall_s / total_wall_s)`;
  - `total_wall_s`: the measured total;
  - `timed_fraction = min(1, sum(stage.wall_s) / total_wall_s)`;
  - `gpu_telemetry`: true if any stage has non-null `gpu_s`, including zero.
- Profile facts are `{profile_complete, timed_fraction, gpu_telemetry}` plus common `tokens_known` and `gpu_busy_known`. `profile_complete` is true when the command exits 0 and both timing inputs validate, even when coverage is below 90%. The gate requires `profile_complete` and `timed_fraction >= 0.9`. Low coverage preserves the packet and fails the gate.

## C/receipts/ and stage failure signatures
- Every box command (uploads, probe, setup attempts, anchor execution, profiling) runs through `m5/boxrun.sh`; every receipt is `C/receipts/NNNN-<operation>.json`. Operations are `upload`, `probe`, `setup`, `anchors`, `profile`; numbering continues across existing receipts. Receipt/log IDs contain no benchmark labels.
- Receipts use the existing boxrun format: `{name, rc, timed_out, wall_s, fetched, started_utc, ended_utc}`. `name` is the receipt ID; `rc` is an integer remote exit code or null; `timed_out` and `fetched` are booleans; `wall_s` is nonnegative integer elapsed seconds; timestamps are UTC strings. Remote `out/` is fetched using the unchanged boxrun interface. Receipt contents stay in control; runtime logs stay in agent results.
- Failed reproduce/profile signatures have fixed `error_class`: `infra` for unavailable box execution/receipts, failed upload, or failed fetch after a successful command; `install` for failed setup after the bounded repair; `anchor` for an anchor-run failure or a failed anchor; `parse` for missing/invalid output files, unavailable harness files, or incomplete profile coverage. Exit codes are 4 for anchor failures and 2 for the other failures. `infra` is added to the shared v1 error-class enum so the v2 envelope remains v1-valid. Box/fetch stdout and stderr are never copied into operator signatures.
- Numeric ratio facts accept finite JSON numbers, including integer spellings such as `0` and `1`; booleans remain invalid. This permits fully timed profiles to emit the capped fraction `1`.
- Every stage records its own elapsed wall-clock seconds in v1 `wall_s`, excluding signature emission. SKIPPED stages measure only their skip handling, never the prior stage's duration.
- Runner results add boolean `tokens_known`, true when the provider reports input/output usage (including reported zeros). wf exposes `agent.usage()` as a cumulative snapshot `{calls, tokens_in, tokens_out, unknown}`; `unknown` counts runner attempts without usage. Repairs, failed attempts, shadow calls, and fallbacks all contribute; cached calls do not incur usage. Compatible runners without `tokens_known` are accepted when their input/output counts are integers.
- Stages aggregate reported input/output counts into v1 `tokens_in`/`tokens_out`; `facts.tokens_known` is true only when every runner attempt in that stage reports usage. With no attempts, existing unknown/null facts remain unchanged. Unknown counts retain numeric zero placeholders required by v1. `gpu_busy_known` remains false for reproduce/profile; stage GPU telemetry is reported separately. Downstream scientific stages are skipped after either failed gate; takeaways still runs.

## A/PREDICTIONS.json (written by the seal agent; checked, then sealed)
- `predictions`: an array, one item per feasible method, with unique methods taken from the menu ["data-parallel over inputs", "batching", "multi-GPU", "ensembles", "pipelining"]. Each item has:
  - `expected_speedup_interval` {low > 0, high >= low};
  - `outcome_vs_compute_points`, holding for every value in compute_budgets one {compute_budget, predicted_outcome, uncertainty}, all non-empty.
- Required non-empty keys: equivalence_metrics, paired_seed_tests, sample_sizes, confidence_rule, hardware_cost_basis, timing_scope, minimum_worthwhile_gain (a number > 1), evaluation_inputs, splits, compute_budgets (at least 3 distinct positive numbers), repetitions (an integer >= 5), warmup, scheduling_order and equal_outcome_target.
- Seal: C/seals/NNNN.json {sha256, path, utc}. The sha256 is over the canonical JSON: keys sorted recursively, array order kept, compact separators, UTF-8. Numbering continues; nothing is overwritten.
