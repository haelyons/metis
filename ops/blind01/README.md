# blind-01 operator tooling (copies)

The scripts and prompts the blind operator used for blind-01 m5, copied from `~/.cache/blind01/` and `~/.claude/hooks/` so they can be audited. The live copies stay in those locations; these are snapshots as of 2026-10-31.

- `blind_guard.py`: PreToolUse hook that keeps the operator's session blind to experiments/blind-01 content.
- `blind_read.py`: the operator's only reader of run metadata (signature fields, enum facts, receipts, box).
- `new_run.py`, `retry38.sh`, `commit_run.sh`: run creation, the run chain and its commit step.
- `backfill_blind.py`: commits uncommitted blind evidence unread.
- `intake_check.md`/`.sh`: the authorized reader on Claude Opus (restricted mode). Output in `experiments/blind-01/m5/intake_check/`.
- `intake_check_codex.md`/`.sh`: the Codex cross-check, with an independent phase A and then alternatives. Output in `m5/intake_check_codex/`.
- `intake_acquire.md`/`.sh`: the Codex acquisition pass. Output in `m5/intake_acquire/`.
- `intake_mirror.md`/`.sh`: the Codex mirror reader after the owner approved the unverified mirror (2026-10-31, option 2). No new search: it records the candidate's URLs, sizes and SHA-256, re-fetches to check them, keeps the provenance `unverified_mirror` and writes the run5 brief addendum. Output in `m5/intake_mirror/`. The same day `intake_acquire.md` was amended so an unverified mirror counts as usable only with the owner's approval.
- `run5_diag.md`/`.sh`: read-only Codex diagnosis of run5's reproduce `infra` failure (no network). Output in `m5/run5_diag/`; it led to U44 (chunked harness uploads).
- `run6_diag*.md`/`.sh`: three read-only Codex diagnoses of run6's setup failures (the third may look up package-index metadata only). Outputs in `m5/run6_diag*/`; they led to U45 (apt from enabled sources).
- `run7_diag*.md`/`.sh`: two read-only Codex diagnoses of run7's setup failures (no network). Outputs in `m5/run7_diag*/`; they led to U46 (setup four repairs).
- `run8_family.md`/`.sh`: a check-only Codex reader of run8's call records: whether the Codex usage outage changed which family answered (it did not). Output in `m5/run8_family/`.
- `run8_diag*.md`/`.sh`: two read-only Codex diagnoses of run8's anchors failures (no network). Outputs in `m5/run8_diag*/`; they led to U47 (finish-first timing for setup, anchors and profile). `retry38.sh` since then gives the pipeline 46,800 s and the box `--max-hours 14`, one hour beyond the 12 h run ceiling.
- `run9_obs.md`/`.sh` and `run9_diag*.md`/`.sh`: Codex readers of run9 (reproduce PASS, profile FAIL parse). They found a CPU-only published baseline and Nsight 2025 writing empty skipped reports, which led to U48.
- `retry44.sh` (U48) and `retry45.sh` (U48 correction), with their prompts `u48*.md`: Codex implements, Opus writes tests from SCHEMAS.md with the implementation Read-denied.
- `run9_replay.md`/`.sh`, `run9_replay2.md`/`.sh`, `run9_par.md`/`.sh`, `run9_scale.md`/`.sh` and `run9_scale2.md`/`.sh`: the owner's neutral assessment of run9. The replays ran the summariser and gate on saved files and showed that merged U48 used phrases Nsight never prints. The others covered the workload's parallel structure and what the reduced-scale reproduce pass establishes.
- `run9_outputs.md`/`.sh`: Codex reader of run9's per-unit outputs and costs; it showed the host-only condition (U49) holds on run9's saved profile.
- `run10_harness*.md`/`.sh` (three attempts) and `run10_review*.md`/`.sh` (independent reviews), with `run10_why`, `run10_mech`, `run10_inputs` and `run10_diff`: unit files for the equivalence check. The command-line selector has no effect; the usable route is a restricted copy of the prepared input list holding original records, passed through an input the measured command already accepts (owner decision 2026-11-01). `run10_harness3` is the one used; run9's own `run_command.sh` has an inherited path conflict, recorded separately.
- `retry46.sh` (U49), `retry47.sh` (U50a, U51) with prompts `u49*.md`, `u50a*.md`, `u51*.md`; `u50.md`/`u50_t.md` are the held whole-U50 prompts, superseded by U50a. `retry48.sh` is `retry38.sh` with run9's box type first, used for run10.
- `run10_post.md`/`.sh` and `run10_post2.md`/`.sh`: Codex readers of run10's unit equivalence check (`units_match` true). They found the match non-vacuous and the subset log's errors inherited from run9, but could not establish by reading which paths the measured command writes in the shared run directory; the probe now counts them (`shared_changes`).
- `run11_post.md`/`.sh` and `run11_post2.md`/`.sh`: Codex readers of run11's unit probe (measured, factors 1.56 and 2.30). `intake_check_post.py --dir run11_post` also prints a deterministic summary of `concurrency.json` (fixed arm labels, booleans, ratios and counts only). The readers found the gain comes from CPUs left idle in serial mode, new library warnings only in concurrent logs (no effect on results), and compared output lists that do not cover every analysis-used result.
- `blind_read.py`: fact keys may contain digits (`units_factor_2`, `units_factor_4`), and `units_outcome` is an allowed enum.
- `retry49.sh` (U50b probe unit mode, U52 standalone unit probe) and `retry50.sh` (U52 follow-up: the four new null facts in two older suites' exact fact checks), with prompts `u50b*.md`, `u52*.md`.
- `new_run.py`: creates a run's `args.json` from run1's; options `--addendum`, `--harness-from=<folder>`, `--stop-after-profile`, `--units-check=<run>`, `--units-probe=<run>` (the last two are mutually exclusive).
- `blind_guard.py`: copy of the operator's PreToolUse hook (`~/.claude/hooks/`), which keeps the operator's tools off blind content; its launcher allowlist covers the `new_run.py` options above.
- blind-02 (2026-11-02, the owner's refined seed): the same tools serve every blind experiment `experiments/blind-NN`. `blind_guard.py` covers any `blind-NN` name or path, with blind-01 decisions unchanged (`test_guard.py <old guard> <new guard>` checks parity on blind-01 calls and coverage on blind-02 and a later name). `blind_read.py` accepts any blind m5 run root. `new_run.py` creates a new experiment's run1 without a run1 to copy: run1's keys, `blind` true, the experiment's own `m5/BRIEF.md`, refused while that file is missing, empty or still byte-identical to the operator's template (checked by hash, never read). `retry51.sh` is `retry48.sh` whose commit also adds the experiment's `m5/BRIEF.md` unread. The operator wrote the template with a file tool, so when the owner filled it the session's changed-file notice showed the operator the seed: the operator of blind-02 is not blind to its brief (owner: continue with this operator, 2026-11-02). Templates the owner fills are made by shell copy from now on.
- `b02_materials.md`/`.sh`: the first blind-02 reader (Codex, reachability checks only). The seed refers to cases and materials by pointing at blind-01, which the pipeline's intake agent may not read; owner 2026-11-02: a Codex addendum copies the case identities, prepared inputs, reference locations and software pins from blind-01's records, and the 2026-10-31 mirror approval extends to blind-02. Output `blind-02/m5/b01_materials/BRIEF_run1.md` (the seed's exact bytes plus a labelled section); `new_run.py --addendum=b01_materials`. `intake_check_post.py --exp blind-02 --dir b01_materials` checks the prefix, the section heading, `unverified_mirror`, that the section names no `experiments/` path, and counts hashes.
- blind-02 run2 (2026-11-02): `run2_progress.md`/`.sh` (Codex; never started, Codex at its usage limit) and `run2_progress2.md`/`.sh` (the same questions on Opus, restricted, no network tools): a read-only progress check during the run. `blind_read.py` now also prints counts of fixed ssh error phrases in `pipeline.log`, per-stage fetched output sizes (bytes and file counts) and the five fixed menu methods' bounds (bound, feasible, k, p). `retry52.sh` builds U53 (incremental fetch through a per-run local mirror; contract 49c8f599) after waiting for Codex, with prompts `u53.md`/`u53_t.md`.
- `run2_trace.md`/`.sh`/`_post.py`: a Codex reader (launched by an earlier operator session on 2026-11-03, committed unread afterwards as 14be826c) that traces the seed's comparisons through run2 and what stopped it; enums only to the operator.
- Science route (owner 2026-11-03: continue within the seed through the tree/card and measure routes; a content-reading scientific agent prepares the inputs and, after each result, assesses it and chooses the next test; the operator stays metadata-only): `sci.sh <NN> <sNN>` runs one step (Codex, Opus restricted fallback) on `sci_protocol.md` plus that step's brief `sci_<sNN>.md`, in `experiments/blind-NN/science/<sNN>/`; `sci_post.py` validates `status.json` against `sci_<sNN>.enums.json`, `NEXT.json` (tree, measure, m5 or stop), `tree_args.json`, `predictions.json` and `outcomes.json` (Brier of the previous step's predictions, numbers only), then commits the step unread. `sci_tree.sh <NN> <sNN>` runs the tree a step chose (Codex family) only when the step and the operator's predictions (`m5/predictions/tree_<sNN>.md`) are committed unchanged. `tree_read.py` prints a tree run's totals, call states and roles, and its calibration records' states and numbers. `blind_commit.py <NN> <folder> <message>` commits one blind folder unread (secret scan, 95 MB limit). `new_run.py` gained `--brief-from=sNN` (an m5 run on a science step's brief, the step committed, its flags equal to the step's) and `--stop-after-reproduce`; `blind_guard.py` allows both.
- `retry53.sh`: `retry51.sh` for calibration runs a science step chose (owner rule: a calibration box run stays under USD 20): box types priced at most USD 3.29/h, box `--max-hours 6` (the launcher's watchdog terminates it), pipeline timeout 20700 s; `new_run.py --brief-from` sets `args.run_ceiling_s` 19800. `tree_read.py <NN> latest` reads the newest tree run.
- run5 (2026-11-03) found that a Claude understudy can read only its `--add-dir` folders (`dut/pipeline/idea/wf.js` callModel; live check: DENIED outside, read with the folder added), so a brief in `science/` was unreadable to the Claude intake while Codex was at its usage limit. `new_run.py --brief-from` now copies the brief into `<run_root>/brief/` and passes that folder in `args.add_dirs` (an existing wf.js input; no pipeline change). `sci_s06.md`: the science step that re-decides with this finding.
- `intake_check_post.py`: validates each reader's status as fixed enums (all the operator sees), checks the addendum prefix, scans for secrets, then commits and pushes.

The materials the readers downloaded (about 2.4 GB) stay in `~/.cache/blind01/intake_check_dl/` on the operator machine and are not committed. Pushing third-party materials to a remote would re-host them, which the readers' rules exclude.
