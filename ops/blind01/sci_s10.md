## Card calibration (U54)
- Purpose: a calibration run measures a tree card's load-bearing GUESS and PROXY inputs on the card's own protocol, and the measured values return to the card. Owner approval 2026-11-03 (contract gap G2 of the blind-02 science route): the tree's calibration record names those inputs, but nothing passed the record to an m5 run or wrote a measurement back, so a run's result could not be read against the card's value. A measured input outside its band refutes the card's value; that is a result and never fails a stage. The band is the measure route's (`launch.js measure`): `[value/k, value*k]`, with `k` 2.5 for PROXY and 3 for GUESS. Without `args.card`, every stage is unchanged.
- Optional `args.card` is an object with exactly `{result, key}`: `result` is a non-empty path, resolved relative to the pipeline working directory, to a tree run's `result.json`, and `key` is a non-empty string. The card's record is the entry of that file's `calibration` array whose `key` equals `key`. It must have `state` `"calibration_required"` and a non-empty `required` array whose items each have a unique string `id` matching `^[a-z][a-z0-9_]{0,30}$` and `basis` `"GUESS"` or `"PROXY"`. An invalid `args.card`, a missing or unreadable file, invalid JSON, no matching record, any other state, an invalid `required`, or `args.card` together with `args.units_check` or `args.units_probe` fails intake with `error_class: parse` before any agent call.
- Before the intake agent call, the pipeline writes `A/card.json` atomically with exactly `{source, source_sha256, record}`: `source` is the absolute path of `result`, `source_sha256` the lowercase hexadecimal SHA-256 of its exact bytes, and `record` the matching record unchanged. Every later stage reads this copy, never `result`. The copy is inside the run, so an agent restricted to the run's folders can read it.
- Intake prompt, card mode only: it names `A/card.json` and states that this run calibrates the record's `required` inputs; that EXECUTION.json's representative workload is the protocol of the phases those inputs name (their `measured_by` and `phase.what`), not another workload; and that the record's `anchor`, when it has a numeric `published_value`, is a candidate anchor that intake writes to anchors.json only when it can cite it under the usual anchor rules.

Never the card's own `value`, and never a number not read from this run's output.
- Anchors output gate, card mode only: `out/anchors_measured.json` must hold every `card:<id>` key, each a finite number or null. A missing key or any other value is an output-gate error of the anchors step, repairable like the step's other output-gate errors. `score_anchors.py` ignores the `card:` keys, as it ignores any additional measurement.
- Scoring: after `run_anchors.sh` exits 0 and its output gate passes, before anchor scoring and whatever the anchors score, the pipeline runs `python3 m5/score_card.py <A/card.json> <out/anchors_measured.json> <A/results/reproduce/card_scored.json>`. It writes an atomic JSON object with exactly `{key, source_sha256, rows, inputs_total, measured_total, within_total, refuted_total}`. `key` and `source_sha256` are copied from the card. `rows` follows `required` order, one row per item, each exactly `{id, name, unit, basis, value, band_factor, band_lo, band_hi, measured_value, verdict, gate_passed}`:

  - `band_lo` is `value / band_factor` and `band_hi` is `value * band_factor` when `value` is a finite number above 0; otherwise both are null.
  - `measured_value` is the finite number under `card:<id>`, otherwise null.
  - `verdict` is `"not_measured"` when `measured_value` is null; otherwise `"no_band"` when the band is null; otherwise `"within_band"` when `band_lo <= measured_value <= band_hi`, `"below_band"` below it and `"above_band"` above it.

  - `inputs_total` counts rows, `measured_total` rows with a number, `within_total` the `within_band` rows and `refuted_total` the `below_band` and `above_band` rows.
  - Exit 0 after writing; exit 1 for invalid or missing input or a failed write, with no output file. Diagnostics contain no input content. A scoring failure fails reproduce with `error_class: parse`.
- Card rows never change reproduce's status, gate or `run_valid`: they are measured and reported, as references are.
