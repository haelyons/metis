## Sealed comparison (U57, U58)
- Purpose: compare several published arms on one box under a design fixed before the run. Owner approval 2026-11-03 (contract gaps G1 comparison arms, G3 tolerance and equivalence, G6 compute metadata of the blind-02 science route); requirements from science steps s13 and s15. Arms are published programs or configurations that need no new code. Each invocation runs one arm on one input, and invocations are interleaved on one box. No agent computes a number: every number comes from the pipeline's trusted wall time, from rules fixed before the run and applied by the pipeline, or from a trusted comparator of two arms' outputs. Criteria, margins, reference values and thresholds are fixed by a science step before the run and hidden from the run's agents. Compute is recorded per invocation and covers the arm's own subprocess only. Never change a criterion after a result: every decision uses the sealed design. An outcome that is not supported is a result and never fails a stage. Comparisons that need more than one run are split by the science step into one design per run. Without `args.comparison`, every stage is unchanged.
- Optional `args.comparison` is an object with exactly the key `design`: a non-empty path, resolved relative to the pipeline working directory, to a design JSON file. It is exclusive with `args.card`, `args.units_check` and `args.units_probe`. The design is exactly `{arms, inputs, outputs, metrics, replicates, warmup, order_seed, budget_s, bootstrap_seed, comparisons}`:
  - `arms`: 2 to 5 items, each exactly `{id, what}`; ids `"A0"`, `"A1"`, ... in order; `what` a non-empty string. `A0` is the published baseline that intake and reproduce handle as usual.
  - `inputs`: 1 to 10 items, each exactly `{id, spec}`: `id` a unique string matching `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`; `spec` any JSON value (pins, case, configuration).
  - `outputs`: 0 to 10 items, each exactly `{name, what, format}`: a logical result each arm writes for an input, compared across arms. `name` unique, matching `^[a-z][a-z0-9_]{0,30}$`; `what` a non-empty string; `format` `"bytes"`, `"text_numbers"` (every number in the file's UTF-8 text, in order, as matched by `[-+]?(\d+\.?\d*|\.\d+)([eE][-+]?\d+)?` together with `nan`, `inf` and `-inf` tokens) or `"json_numbers"` (every number leaf of the JSON document, in document order; booleans are not numbers).

  - `replicates` an integer from 1 to 30; `warmup` an integer from 0 to 3; `order_seed` and `bootstrap_seed` integers; `budget_s` a positive integer, the evaluate stage's time budget for this comparison. When `args.run_ceiling_s` is present, `budget_s` must be below it.
  - `comparisons`: 1 to 12 items, each exactly `{id, arm, against, measure, criterion, direction, unit, pairing, rule, confidence, margin, threshold, reference, parts}`:

    - `measure` is exactly `{metric}` (a metric name) or exactly `{output, comparator}` (an output name and one of `"exact"`, `"elementwise_abs"`, `"elementwise_rel"`, `"elementwise_abs_plus_rel"`). An output comparison needs an arm as `against`.
    - `criterion` `"equivalence"`, `"non_inferiority"`, `"superiority"`, `"ratio_at_least"` or `"agreement"`. `agreement` is the criterion of every output comparison and of no metric comparison.
    - `direction` `"higher_better"`, `"lower_better"` or `"two_sided"`: the metric as measured (for wall seconds, `lower_better`). `equivalence` and `agreement` use `two_sided`; `non_inferiority` and `ratio_at_least` use `higher_better` or `lower_better`; `superiority` takes any.

    - `pairing` `"paired_replicate"` or `"unpaired"`; output comparisons use `paired_replicate`.
    - `rule` `"all_pairs"` or `"bootstrap"`; `confidence` a number in `[0.5, 1)` for `bootstrap` and null for `all_pairs`. Output comparisons use `all_pairs`.
    - `margin`: null, `{"abs": x}`, `{"rel": y}` or `{"abs": x, "rel": y}` with `x` and `y` finite and nonnegative. For an output comparison it is the comparator's tolerance: `elementwise_abs` needs `abs`, `elementwise_rel` needs `rel`, `elementwise_abs_plus_rel` needs both, `exact` needs null. For a metric comparison it is null, `abs` or `rel`; `rel` scales by `abs(reference)` against a reference, else by `abs(mean of the against arm's values)` for the same unit.

Too few values gives outcome `"void"` with reason `"insufficient_replicates"`; no values at all gives reason `"missing_values"`.
