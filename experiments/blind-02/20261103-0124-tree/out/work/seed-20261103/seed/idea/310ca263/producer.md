Build CPU-only unit manifests and controller. Use four specified apo cases, immutable input/reference hashes, source/dependency/binary hashes, CPU OpenMP binary, OMP_NUM_THREADS=26, fixed full-host affinity, unchanged flags `-N50 -t1 -v1.2 -e1 -d1 -a-45 -b1 -f3 -r3600`. Keep original output path names inside isolated arm/repeat roots. Generate and retain all 50 final poses per case, every repeat. No GPU kernels, MPS, dense search, thread reduction, input changes, or scientific sample expansion.

Arms: a = original four-case serial invocation; b = four separate serial unit invocations; c2 = same units, width 2; c4 = same units, width 4. Seal order a,b,c2,c4,c4,c2,b,a. Two complete four-case blocks per arm; 32 docking jobs, 1600 retained pose artifacts, 200 unique case/rank slots. Initial a and b occupy anchor phase. Check historical frozen CPU artifacts against a, then b against a, before concurrent arms. Missing reference or any substantive mismatch stops later arms. Exact byte equality for prepared PDBs, docking scientific records, every final pose, stable paths and file inventories; zero differing scientific bytes. Exclude only predeclared volatile logs/timestamps; no post hoc normalization. Check shared input hashes and unauthorized shared writes before/after every block. Compare every later output with initial a, then compare final a as drift control.

Time complete invocation-to-final-pose blocks, including unit launch, docking, pose generation and required file handling. Also retain docking-only timings. Collect CPU seconds, effective cores, busy fraction, context switches, memory/thread peaks, shared-change counts and GPU activity. All jobs share same 26-vCPU allocation; width 4 requests 104 OpenMP threads, deliberately preserving original threads rather than tuning concurrency.

For each c2/c4 repeat, speed factor = linearly interpolated nearby a block time / concurrent block time. Advance width only if both repeats give factor >=1.05 and all equality checks pass. If both widths pass, choose larger minimum repeat factor, tie to smaller width. Report b separately as launch-overhead control. Report both raw factors, minimum and mean; two repeats are a screening gate, not a confidence interval. Failure or discordant repeats leads next to separately sealed serial variability control, never a lowered threshold or extra opportunistic repeats. High CPU busy without gain deprioritizes unchanged-thread concurrency; low busy without gain motivates launch/I/O analysis. Thread 13 belongs only in separately sealed follow-up.
