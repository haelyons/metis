# Working notes — I1 drift probes on the autoformalizer: programme mapping

Task: find 1–3 existing programmes whose pipeline this card (probes on open Lean
autoformalizers, trained on machine-made errors, vs expert-label-trained probes, scored on
real expert-found misformalizations) would feed. Cite URL + supporting sentence per claim.
Check whether each has already run the experiment.

## Card's targeted step
Semantic-alignment checking of autoformalized Lean 4 statements: does the formal statement
mean the same as the informal one? Today this is done by (a) external LLM judges, (b) human
experts, (c) nothing (tolerated noise). The card proposes a cheap alternative: linear probes
on the formalizer's own hidden states, labels generated by machine corruption at scale.

## Candidate 1: Goedel-Prover / Goedel-LM (Princeton PLI + Tsinghua, Amazon, Meta FAIR, Numina)
Sources: https://goedel-lm.github.io/ , https://arxiv.org/html/2502.07640v2 , https://github.com/Goedel-LM/Goedel-Prover
- Pipeline step: "Statement Formalization" -> "Quality Assessment" (CC test + FC test) before
  expert iteration. Exactly the card's step.
- Practice: two formalizers (Qwen2.5-Coder-32B trained on Lean Workbook pairs; one trained on
  170K Claude-sonnet-3.5 formalizations), 16 formalizations/problem, "Training completed in
  under 24 hours using 8 H100 GPUs." FC test: "Uses Qwen2.5-72B-Instruct for assessment",
  "Generates 4 independent judgments per statement", "Statements below 0.5 FC score are
  filtered out". Scale: 928K informal -> 1.64M kept; total 1.78M formal statements.
- Key quote (arxiv abstract): "LLMs are used to check that the formal statements accurately
  preserve the content of the original natural language problems."
- If lever: probe replaces/augments the 72B judge on ~1.78M statements; could run inside
  generation during expert iteration. If not: validates their LLM-judge choice; nothing changes.
- Already done? No — LLM-as-judge only, no hidden-state probes, no machine-vs-expert label
  comparison. FormalAlign (separate group) is closest prior, synthetic negatives only.

## Candidate 2: Project Numina / Kimina (Numina & Moonshot AI Kimi team)
Sources: https://arxiv.org/html/2504.11354v1 , https://huggingface.co/AI-MO/Kimina-Autoformalizer-7B ,
https://projectnumina.ai/models-datasets-tools
- Pipeline step: training Kimina-Autoformalizer-7B via expert iteration with LLM judging, and
  building the ~200k problem set for Kimina-Prover RL (~100k autoformalized + ~10k human-annotated,
  resampled 1:1). Released NuminaMath-Lean 100K.
- Practice (direct quotes from arXiv 2504.11354v1):
  - "there is no straightforward way to verify the correctness of a generated formal problem
    statement with respect to the natural language input" (§2.1)
  - "We then employ a QwQ-32B as a judge to evaluate the semantic correctness of each remaining
    formalization, using a handcrafted prompt to guide its assessment." (C.2.2); unanimous voting
    over multiple judge samples to cut false positives.
  - "we monitor model outputs throughout training with Lean 4 experts and gradually improve the
    judge prompt over iterations" (C.2.2)
  - "We note that this method required careful expert monitoring as we observe that the model
    would repeatedly make mistakes that the LLM judge model cannot catch, as long as it passed
    compilation." (C.2.3) <- the exact gap the card targets
  - "we use a human-curated test set of size approximately 1,000 and optimize an LLM judge prompt
    on this set" (C.2.3); autoformalizer reaches "90% one-shot compilation rate and 66% accuracy".
  - Dedicated annotation team for human statements/proofs (C.1 step 4).
- If lever: a probe on Kimina-Autoformalizer-7B (an open 7B formalizer, exactly the card's model
  class) catching mistakes "the LLM judge model cannot catch" reduces reliance on the expert
  monitoring queue and the ~1k-label judge calibration; lets the autoformalized share of the RL
  problem set scale beyond the ~10k human anchor. If not: keeps QwQ-32B judge + experts;
  confirms the human annotation pipeline is not replaceable by machine-labelled probes.
- Already done? PARTLY. FormalAlign (ICLR 2025, arXiv 2410.10135; authors Jianqiao Lu, Yingjia
  Wan, Yinya Huang, Jing Xiong, Zhengying Liu, Zhijiang Guo — Jing Xiong/Zhengying Liu overlap
  with the Kimi team) trains hidden-state-based alignment scoring on synthetic misalignments
  ("Evaluated across four benchmarks augmented by our proposed misalignment strategies"), but it
  is a separately fine-tuned Mistral-7B evaluator tested on synthetic negatives — not linear
  probes on the production formalizer validated against expert-found real errors, and not a
  machine-label vs expert-label comparison. Kimina's production loop still uses QwQ judge +
  experts.

## Candidate 3: Google DeepMind AlphaProof (incl. 2026 AlphaProof-Nexus research paper)
Sources: https://deepmind.google/blog/ai-solves-imo-problems-at-silver-medal-level/ ,
https://arxiv.org/pdf/2605.22763v1
- Pipeline step: "formalizer network" (fine-tuned Gemini) translating ~1M informal problems into
  Lean for the RL training library; contest problems hand-translated by humans; 2026 follow-up
  autoformalizes open research questions (OEIS, Erdős problems) for an agent.
- Practice (quotes):
  - "We established a bridge between these two complementary spheres by fine-tuning a Gemini
    model to automatically translate natural language problem statements into formal statements,
    creating a large library of formal problems of varying difficulty."
  - "Around one million informal math problems are translated into a formal math language by a
    formalizer network." (infographic caption)
  - "First, the problems were manually translated into formal mathematical language for our
    systems to understand." (IMO 2024 contest problems)
  - "We used Gemini to autoformalize 492 open questions from the OEIS" (arXiv 2605.22763);
    "AlphaProof cost approximately 27.5 TPU hours ($60 USD) per problem on v6e TPUs."
- If lever: scalable semantic check on the ~1M training library and on autoformalized open
  problems before spending ~27.5 TPU-hours each; fewer hand-translations. If not: nothing
  changes — training noise tolerated, high-stakes formalization stays manual.
- Already done? No public evidence of probe-based misformalization detection; blog describes
  formalizer + manual contest translation only. Status: no.

## Prior art check (the card's [formalalign])
FormalAlign, ICLR 2025, https://arxiv.org/abs/2410.10135 — "the first automated framework
designed for evaluating the alignment between natural and formal languages in autoformalization";
dual loss (autoformalization CE + contrastive on hidden states); fine-tuned Mistral-7B;
"Evaluated across four benchmarks augmented by our proposed misalignment strategies" — synthetic
negatives only, no expert-labelled real-error test, no machine-vs-expert label training
comparison, no linear probes on frozen formalizers, no cross-model probe transfer. This matches
the card's "closest prior: not on this axis".

## Gaps / caveats
- No programme publishes an expert-labelled misformalization test set; Kimina's ~1,000
  human-curated set (private) is the closest. The card's eval set must be built from scratch.
- DeepMind's formalizer is closed (Gemini); probes need activation access — internal-only
  transfer, not replicable externally. Card is scoped to open models ≤32B, which covers
  Kimina-Autoformalizer-7B, Goedel/StepFun formalizers, Herald.
- Card tests competition/conjecture statements; research-level definition formalization
  (OEIS/Erdős in AlphaProof Nexus) is at/beyond its stated scope.
- FormalAlign-style contrastive training on hidden states ≠ frozen-model linear probes; whether
  cheap probes transfer across formalizer checkpoints ("copied across models") is untested
  everywhere.
