# PHYSICAL-WIDENER — related problems around FRAMER that are compute constrained

Widened counting rule: a related problem counts as compute constrained (a) when it is still open whether more parallel compute would change its answer, and (b) when compute is already known to bind there (marked `settled:` in compute_open); also (c) when its answer simply takes long because its steps run one after another, even where more hardware would not change the answer, only how soon it arrives.

## W1. In-silico enumeration of capsid–receptor complexes (AlphaFold-class sampling)

Sampling capsid variant × receptor ectodomain pairs (AAVR PKD domains, LY6A/LY6C1, CA4, ALPL, LRP6, glycans) with AlphaFold-class modelling, docking and refinement, to see whether a compact, transferable binding-signature class exists. The one published AAV application used AlphaFold-Multimer plus RosettaRemodel to rank capsids against LY6C1/CA4 and reported that the predicted PHP.C2–LY6C1 pose changed with the AlphaFold-Multimer version (https://pmc.ncbi.nlm.nih.gov/articles/PMC10115422); ensemble benchmarks run up to 480 predictions per target (32 seeds × 5 models × 3 runs, 3 recycles each) (https://www.nature.com/articles/s41467-024-46715-9).

- root_link: Bears on Q1 (measurability) and on whether a compact transferable signature class exists — framer §6.1.
- compute_open: More parallel compute buys model runs/seeds per (variant × receptor) pair; the largest sampling reported in a cited source is 480 AlphaFold2 predictions per target (https://www.nature.com/articles/s41467-024-46715-9); above that it is unknown whether more seeds/MSA subsamples converge on one interface footprint or keep alternating, since the only AAV application found the predicted pose depend on the AlphaFold-Multimer version (https://pmc.ncbi.nlm.nih.gov/articles/PMC10115422).
- sequential: none: each (variant × receptor) pair and each seed is an independent prediction job only ~3 recycle iterations deep, so the enumeration splits directly across GPUs.
- sources: https://www.nature.com/articles/s41467-024-46715-9 ; https://pmc.ncbi.nlm.nih.gov/articles/PMC10115422

## W2. Physics-based sampling of capsid–glycan–receptor binding and pH-dependent dissociation

All-atom MD and free-energy calculations of capsid–glycan/capsid–receptor binding and dissociation under endosomal pH — the layer where H_suff/H_cond/H_insuff is decided (framer §6.2). Protein–protein association has been reached only by aggregating adaptive ensemble trajectories (2 ms total) with Markov modelling (https://doi.org/10.1038/nchem.2785; http://ftp.mi.fu-berlin.de/pub/ag-cmb/pyemma-workshop-2018/slides/pyemma-2018-msm-introduction.pdf).

- root_link: Bears on Q2 (causal sufficiency) — whether binding energetics plus trafficking kinetics jointly determine transcytosis vs. retention (framer §6.2).
- compute_open: More parallel compute buys aggregate sampling (ensemble members × trajectory length); the largest amount reported in a cited source is 2 ms of aggregate adaptive MD for a ~100,000-atom protein–protein association (http://ftp.mi.fu-berlin.de/pub/ag-cmb/pyemma-workshop-2018/slides/pyemma-2018-msm-introduction.pdf); above that it is unknown whether more sampling would change any transcytosis-vs-retention ranking, since no capsid–receptor dissociation free energy at endosomal pH has been published.
- sequential: One answer waits on time-stepped integration where each step's forces and positions wait on the previous step (2–4 fs per step, so 1 µs is 2.5–5×10^8 steps: https://manual.gromacs.org/current/user-guide/mdrun-performance.html); the answer needs tens to hundreds of independent replica runs, and one 50k-atom run keeps one GPU essentially saturated at ~350 ns/day (https://images.nvidia.com/content/tesla/pdf/Molecular-Dynamics-July-2017-MB-slides.pdf ; http://ftp.mi.fu-berlin.de/pub/ag-cmb/pyemma-workshop-2018/slides/pyemma-2018-msm-introduction.pdf). The steps of one trajectory must run in order; the change that runs work at the same time is replacing one long trajectory with many short independent replicas pooled in a Markov state model (or λ-window replica exchange), which pays off only if the rare unbinding/sorting event is likelier from many independent starts than inside one long run; the nearest source that tried it is adaptive ensemble MD with Markov modelling (https://doi.org/10.1038/nchem.2785), with replica-exchange FEP packed onto one GPU via NVIDIA MPS as the nearest throughput measurement (https://developer.nvidia.com/blog/maximizing-openmm-molecular-dynamics-throughput-with-nvidia-multi-process-service).
- sources: https://doi.org/10.1038/nchem.2785 ; http://ftp.mi.fu-berlin.de/pub/ag-cmb/pyemma-workshop-2018/slides/pyemma-2018-msm-introduction.pdf ; https://developer.nvidia.com/blog/maximizing-openmm-molecular-dynamics-throughput-with-nvidia-multi-process-service

## W3. Cryo-EM/cryo-ET reconstruction of capsid–receptor footprints

Single-particle reconstruction and tomography of capsid–receptor complexes, to obtain the capsid surface residues, receptor domain and stoichiometry of the "binding signature" (framer §1.4). AAV2–AAVR structures exist at 2.8 Å (PKD1-5) and 2.4 Å (PKD1-2) (https://www.rcsb.org/structure/6IHB ; https://www.rcsb.org/structure/6NZ0), while tomographic averaging of the same complex leaves the distal PKD1 domains visible only at ~20 Å (https://pmc.ncbi.nlm.nih.gov/articles/PMC9278096).

- root_link: Bears on Q1 (measurability) — whether footprint, receptor domain and stoichiometry can be resolved at molecular resolution (framer §1.4, §3.1).
- compute_open: More parallel compute buys processed particles/classification jobs and hence resolution; the largest amount reported in a cited source is 30,515 AAV2 particles giving a 1.86 Å capsid map (https://www.nature.com/articles/s41467-018-06076-6); above that it is unknown whether more particles and finer classification would resolve the flexible AAVR PKD1/PKD3-5 densities that tomographic averaging still shows only at ~20 Å (https://pmc.ncbi.nlm.nih.gov/articles/PMC9278096).
- sequential: One answer waits on an ordered processing chain — motion correction → CTF estimation → particle picking → 2D classification → 3D classification → 3D refinement — where each stage consumes the previous stage's particles and each classification/refinement runs tens of iterations, totalling roughly a dozen ordered stages per dataset, with several half-map/classification runs per answer and one GPU kept busy for days per refinement (https://pmc.ncbi.nlm.nih.gov/articles/PMC9278096). These stages must run in order, because each needs the previous stage's output, so wall-time is the sum of the stages rather than their maximum.
- sources: https://www.nature.com/articles/s41467-018-06076-6 ; https://pmc.ncbi.nlm.nih.gov/articles/PMC9278096 ; https://www.rcsb.org/structure/6NZ0

## W4. Machine-guided search over capsid sequence space (library design)

Training sequence-to-function models on deep mutational scans and searching capsid sequence space for the panel of matched-affinity/different-footprint variants a decisive answer requires (framer §3.4). ML-guided diversification of one 28-aa AAV2 segment generated 201,426 designed variants yielding 110,689 viable capsids, 57,348 beyond natural serotype diversity (https://www.nature.com/articles/s41587-020-00793-4), building on the complete first-order AAV2 landscape across 735 positions (https://pmc.ncbi.nlm.nih.gov/articles/PMC7197022).

- root_link: Bears on the decisive-answer requirement for a ≥50–100 capsid panel spanning matched-affinity/different-footprint and receptor-null variants (framer §3.4).
- compute_open: settled: wider machine-guided search is a known lever for design yield — 201,426 ML-designed AAV2 variants produced 110,689 viable capsids, 57,348 beyond natural serotype diversity (https://www.nature.com/articles/s41587-020-00793-4).
- sequential: none: scoring each candidate sequence and each generated variant is an independent per-sequence evaluation, so the search over millions of candidates already splits into independent pieces across GPUs.
- sources: https://www.nature.com/articles/s41587-020-00793-4 ; https://pmc.ncbi.nlm.nih.gov/articles/PMC7197022

## W5. Whole-virion atomistic MD of capsid dynamics and stability

All-atom simulation of entire capsids (a few million atoms with solvent, up to 10–100 million for complete virions) to test which binding-altering mutations also destabilise the capsid — the assembly confound in framer §3.5. A whole-virion run has been taken to only 10 ns on a supercomputer (https://i2.riken.jp/download/Q16302.pdf), and a major capsid program names capturing long-timescale dynamics of 10–100 million-atom capsids as its central compute challenge (https://www.ks.uiuc.edu/Research/dbps/dbp_1.html).

- root_link: Bears on the capsid fitness/assembly confound (framer §3.5) — whether the binding signature is physically realisable on an intact capsid.
- compute_open: settled: whole-virion all-atom MD is already known to be compute-bound — an entire few-million-atom virion has reached only 10 ns per supercomputer run (https://i2.riken.jp/download/Q16302.pdf) while the field's stated goal is multi-microsecond sampling of 10–100 million-atom capsids on petascale/exascale machines (https://www.ks.uiuc.edu/Research/dbps/dbp_1.html).
- sequential: One answer waits on time-stepped integration where each step's forces and positions wait on the previous step — a 10 ns run is 5×10^6 steps at 2 fs (https://manual.gromacs.org/current/user-guide/mdrun-performance.html) and keeps a whole multi-GPU node busy for weeks — and the answer needs a handful of independent runs (the RIKEN study ran several ion-condition/force-field combinations: https://i2.riken.jp/download/Q16302.pdf). The steps must run in order inside a trajectory; only the independent condition runs may proceed at the same time, so the change that helps is running those replicas on separate nodes concurrently, which pays off when each condition equilibrates its observable (ion distribution, stability) independently.
- sources: https://i2.riken.jp/download/Q16302.pdf ; https://www.ks.uiuc.edu/Research/dbps/dbp_1.html ; https://manual.gromacs.org/current/user-guide/mdrun-performance.html
