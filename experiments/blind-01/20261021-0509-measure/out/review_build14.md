EXEC_NOTE items 66 and 68 and item 62(iii) require both: the test of record's full output in that file, and the hand-written nine-line list that the operator `diff`s against `PIP_PINS`. The operator's finding 2 reports the T1 outcome (exit 0, 82 packages, `out/pip_pins_resolve_build14.json` 1.0 MB), but the text file holds no command line, no pip version (T0) and no T2 result. The sdist build is the only step of the install that no test has covered, and it is the step that would end a USD 4.31 launch at exit 2. Launch 2's pre-authorisation condition (iii) is therefore not shown. Fix before launch: write the list file, run T0, T1 and T2 on the lines read from `PIP_PINS`, and write the output into the txt file and RUN.md.

2. **BLOCKING.** `run_m4.py` has no static check that neither file opens a path under `out/pip_` or `out/gate` (grep for `out/pip_`, `out/gate` and `pip_release_files` finds nothing). EXEC_NOTE item 67 and item 65 ("the static check of item 67 is part of the selftest cases of this scope") require it, and K6 widened its prefixes. The build return says it was "NOT ADDED" because the scope list does not name it. Item 65 does name it. The selftest group at `run_m4.py:7328-7375` has the `.keys`, upgrade-pip and environment-dump checks but not this one. Neither file opens such a path (the grep is clean), so no run risk follows, but a directive item is unmet.

3. **BLOCKING.** The comment on `PIP_PINS` (`run_m4.py:381-405`) names three sources: `gate_report_build13.md`, `pip_pins_resolve_build11.txt` and `install_pip_install.log`. EXEC_NOTE item 58 and K6 also require `out/pip_release_files_lightdock.txt` as a named source, with the metadata fact that `openmm-cuda==8.1.1.12` requires `openmm==8.1.1` and that this release has a CPython 3.10 wheel. 4. **ADVISORY.** `run_m4.py:463-472` changes `pip_pins_problems`, adding the lone-sibling refusal. Item 64 requires "an `openmm-cuda*` entry without a plain `openmm` entry is rejected", and that case cannot pass without the change. 5. **ADVISORY.** `out/pip_pins_check_build14.txt` line 3 flags `EXTRA-NOT-DECLARED jax-cuda12-plugin[with_cuda]` ("extra with_cuda not in ['with-cuda']"). pip normalises `with_cuda` to `with-cuda`, and K1's listing says so. The report's `.whl` URLs and its `nvidia-cudnn-cu12` entry were not confirmed here because the txt that should record them is empty (finding 1).

6. **ADVISORY.** The test of record resolves in a clean venv with `--ignore-installed`. The box's venv is built with `--system-site-packages` over the image's torch 2.7 and its `nvidia-*` pins, and `remote_run_m4.sh` also leaves `numpy==1.26.4` in `~/.local`. Neither is modelled, so a conflict with the preinstalled set cannot be excluded. The smoke check and the install ceiling bound the cost to an exit-2 void, as in launch 1.
